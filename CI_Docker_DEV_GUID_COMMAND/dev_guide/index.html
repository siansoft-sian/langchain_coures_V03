SET

Start here

Set up the project

Installs Python and packages, turns on commit checks and creates .env.

CI_Docker_DEV_GUID_COMMAND/ci/setup_project.py

How to

  1. Install uv and git.
  2. Clone the project and open its folder.
  3. Run python CI_Docker_DEV_GUID_COMMAND/ci/setup_project.py (use python3 on macOS if needed).
  4. Open .env and fill in any keys it says are empty.
  5. Run the project with uv run search-agent.

Example

First time on a new computer 
$ python CI_Docker_DEV_GUID_COMMAND/ci/setup_project.py
→ Checking that uv is installed
→ Installing Python and packages (uv sync)
→ Turning on the checks that run before every commit (pre-commit)
→ Creating .env from .env.example
✓ Setup done, but these keys in .env are still empty:
    OPENAI_API_KEY
    TAVILY_API_KEY

Good to know: it's safe to run again at any time, because it never overwrites your .env. In VS Code, accept the suggested extensions (Python, Ruff, Docker) so code is formatted when you save.

ENV

Start here

API keys (.env)

Your secret keys. Never uploaded to GitHub, never built into the Docker image.

.env.example

How to add a new key

  1. Add the key with an empty value to .env.example.
  2. Add the same name to REQUIRED_KEYS in src/search_agent/config.py.
  3. Put the real value in your own .env.
  4. Run uv run pytest. A test checks that the two lists match.

Example

.env.example (uploaded, no values) 
OPENAI_API_KEY=
TAVILY_API_KEY=
When a key is missing 
$ uv run search-agent
✗ Missing keys: OPENAI_API_KEY
  Add them to .env (see .env.example), or run: python CI_Docker_DEV_GUID_COMMAND/ci/setup_project.py

Good to know: save_project.py refuses to commit .env, *.pem, *.key and other secret files (see BLOCKED_FILES).

CFG

Start here

Settings (project_config.py)

One file for every setting used by the scripts in CI_Docker_DEV_GUID_COMMAND/ci/ and CI_Docker_DEV_GUID_COMMAND/docker/.

project_config.py

How to

  1. Open project_config.py in the main folder.
  2. Change a value, e.g. BRANCH_PREFIX = "feature/".
  3. Save. The scripts read it the next time they run.
  4. Check the current values with any script's --help.

Example

project_config.py 
# Git and GitHub (CI_Docker_DEV_GUID_COMMAND/ci/ scripts)
MAIN_BRANCH = "main"
BRANCH_PREFIX = "feature/"   # my-idea -> feature/my-idea
SYNC_WITH_MAIN = False

# Docker (CI_Docker_DEV_GUID_COMMAND/docker/ scripts)
IMAGE_NAME = "langchain-coures-v03"
PORTS = ["8000:8000"]        # for a web API

Good to know: to reuse the scripts in another project, copy the CI_Docker_DEV_GUID_COMMAND/ci/ folder and project_config.py together.

Daily Git

BR

Daily Git

Create a new branch

Gets the latest main, creates your branch from it and uploads it to GitHub.

CI_Docker_DEV_GUID_COMMAND/ci/create_branch.py

How to

  1. Save or commit your current work first.
  2. Run python CI_Docker_DEV_GUID_COMMAND/ci/create_branch.py <name>.
  3. Use a short name with no spaces, e.g. add-search-tool.
  4. You are now on the new branch. Start working.

Example

Start new work 
$ python CI_Docker_DEV_GUID_COMMAND/ci/create_branch.py add-search-tool
→ Switching to main
→ Getting the latest main from origin
→ Creating branch add-search-tool
→ Uploading add-search-tool to origin
✓ Branch 'add-search-tool' created and uploaded. You are now on it.

Good to know: run it with no name and it asks you for one. Run python CI_Docker_DEV_GUID_COMMAND/ci/create_branch.py --help for every option.

SV

Daily Git

Save your work

Commits every change, gets other people's changes and uploads your branch.

CI_Docker_DEV_GUID_COMMAND/ci/save_project.py

How to

  1. Run python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "What you changed", as often as you like.
  2. If the commit checks fix a file, the save stops. Run the same command again.
  3. When the work is done, add --main to also update main.
  4. On a conflict, fix the files Git lists, run the command it prints, then save again.

Example

Save during the day 
$ python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "Add Tavily search tool"
→ Staging all changes
→ Committing: Add Tavily search tool
→ Uploading add-search-tool to origin
✓ Project saved and 'add-search-tool' is up to date on origin.
Finished: also move main forward 
$ python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "Finish search tool" --main

Good to know: --main never overwrites main. If main has commits your branch doesn't, it stops and tells you to merge main first.

Run

UV

Run

Packages and running code (uv)

uv installs Python and the exact package versions in uv.lock.

UV_COMMANDS.md

How to

  1. Run the project: uv run search-agent.
  2. Add a package: uv add <package>.
  3. Add a tool only for development: uv add --dev <package>.
  4. After pulling someone else's changes: uv sync.
  5. After adding packages, rebuild Docker with --build.

Example

Add a package and use it 
$ uv add langchain-community
$ uv run search-agent
hello world!

$ uv remove langchain-community   # undo
$ uv tree                         # see what's installed

Good to know: with uv run you don't need to activate .venv. Always commit uv.lock so everyone gets the same versions.

DK

Run

Docker

Builds the project into an image and runs it in a container with your .env keys.

CI_Docker_DEV_GUID_COMMAND/docker/

How to

  1. Open Docker Desktop and wait until it's running.
  2. Run python CI_Docker_DEV_GUID_COMMAND/docker/run_container.py --build.
  3. After changing code or packages, use --build again.
  4. To look around inside: python CI_Docker_DEV_GUID_COMMAND/docker/run_container.py bash.

Example

Build and run 
$ python CI_Docker_DEV_GUID_COMMAND/docker/run_container.py --build
→ Building langchain-coures-v03:latest
→ Running search-agent in langchain-coures-v03:latest
hello world!
Build only 
$ python CI_Docker_DEV_GUID_COMMAND/docker/build_image.py
$ python CI_Docker_DEV_GUID_COMMAND/docker/build_image.py --no-cache   # from scratch

Good to know: the image holds the code as it was when you built it. The container is removed when it stops, and the image stays.

DC

Run

Docker Compose

Starts the app and any extra services (like a database) with one command.

docker-compose.yml

How to

  1. Start everything: docker compose up --build.
  2. To add a database, uncomment the db service in docker-compose.yml.
  3. Stop with Ctrl+C, then docker compose down.

Example

docker-compose.yml with a database turned on 
services:
  app:
    build:
      context: .
      dockerfile: CI_Docker_DEV_GUID_COMMAND/docker/Dockerfile
    env_file:
      - path: .env
        required: false
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: postgres

Good to know: for one container, CI_Docker_DEV_GUID_COMMAND/docker/run_container.py is simpler. More commands are in CI_Docker_DEV_GUID_COMMAND/docker/DOCKER_COMMANDS.md.

Code quality

RF

Code quality

Ruff: lint and format

Finds common mistakes, sorts imports and formats code the same way everywhere.

pyproject.toml

How to

  1. Find and fix mistakes: uv run ruff check . --fix.
  2. Format all code: uv run ruff format ..
  3. Change rules in [tool.ruff] in pyproject.toml.
  4. In VS Code it runs automatically when you save.

Example

Ruff finds an unused import 
$ uv run ruff check .
src/search_agent/main.py:1:8: F401 [*] `json` imported but unused
Found 1 error.

$ uv run ruff check . --fix
Found 1 error (1 fixed, 0 remaining).

Good to know: to keep a line Ruff complains about on purpose, end it with # noqa: CODE, e.g. # noqa: F401.

PT

Code quality

Tests (pytest)

Small checks that prove the code still works after a change.

tests/

How to

  1. Run all tests: uv run pytest.
  2. Add a file in tests/ named test_something.py.
  3. Write functions named test_... that use assert.
  4. Run one test: uv run pytest -k name.

Example

tests/test_config.py 
from search_agent import config

def test_check_env_passes_when_all_keys_are_set(monkeypatch):
    for key in config.REQUIRED_KEYS:
        monkeypatch.setenv(key, "test-value")

    config.check_env()  # should not stop the program
Run them 
$ uv run pytest
4 passed in 0.04s

Good to know: tests never use your real keys. monkeypatch sets fake ones just for the test. In VS Code, run them from the Testing panel.

PC

Code quality

Commit checks (pre-commit)

Run the gitleaks secret scan, Ruff and safety checks before every commit.

.pre-commit-config.yaml

How to

  1. Turned on by python CI_Docker_DEV_GUID_COMMAND/ci/setup_project.py.
  2. Commit as usual. The checks run by themselves.
  3. If a check fixes a file, commit (or save) again.
  4. Run them on all files: uv run pre-commit run --all-files.

Example

gitleaks finds a key in the code 
$ python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "Add search"
Detect hardcoded secrets.................Failed
RuleID:      tavily-api-key
File:        agent.py
Line:        4
Secret:      REDACTED
✗ 'git commit -m Add search' failed
A check fixed a file, so save again 
$ python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "Update agent"
ruff format..............................Failed
- files were modified by this hook
✗ 'git commit -m Update agent' failed

$ python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py "Update agent"
ruff format..............................Passed
✓ Project saved and 'add-search-tool' is up to date on origin.

Good to know: gitleaks blocks API keys, tokens and passwords (rules in .gitleaks.toml). If it stops you, move the key to .env and read it with os.getenv("NAME"). For a false alarm, end the line with # gitleaks:allow. The checks also block leftover <<<<<<< conflict markers and files over 500 KB.

GA

Code quality

GitHub Actions

After every push, GitHub runs Ruff, the tests, a secret scan of the whole history and a Docker build.

check.yml

How to

  1. Push as usual with python CI_Docker_DEV_GUID_COMMAND/ci/save_project.py.
  2. Open the repository on GitHub and go to the Actions tab.
  3. A green tick means everything passed. A red cross means click it to see what failed.
  4. Fix it locally, then save again.

Example

Check the latest run from the terminal (GitHub CLI) 
$ gh run list --limit 3
$ gh run watch          # follow the current run
$ gh run view --log-failed

Good to know: GitHub has no .env, so tests must never need real keys. Add a step to check.yml to run more checks.
